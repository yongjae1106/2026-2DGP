# PRD: 소닉 애니메이션 뷰어 (sonic_animation_viewer.py)

PRE-PRD.md 기준으로 작성한 개발 요구사항 문서. LEC08의 `animation_viewer.py`(커비 버전)와 동일한 패턴을 소닉 스프라이트에 적용한다.

## 1. 배경

LEC08에서 커비 스프라이트 시트를 `clip_draw`/`clip_draw_to_origin`으로 잘라 동작별 애니메이션을 재생하는 뷰어를 만들었다. LEC09는 같은 구조를 소닉 스프라이트(`sonic-sprite.png`, 399x525, `Labs/LEC08_Animation/sonic-sprite.png`에 있는 걸 가져다 쓰거나 LEC09 폴더에 복사)에 대해 반복 구현하는 과제다. PRE-PRD에 "단계별로 구현해서 커밋을 그때그때", "최소 20단계 이상"이 명시돼 있으므로, 전체를 한 번에 작성하지 않고 LEC08 때처럼 잘게 쪼갠 커밋으로 진행한다.

## 2. 목표

- `sonic_animation_viewer.py` 단일 파일로, 소닉 스프라이트의 모든 동작(행)을 순서대로 재생하는 pico2d 프로그램 작성
- 각 동작은 5회 반복 재생 후 1초 정지, 그다음 동작으로 전환
- 모든 동작을 다 돈 뒤에는 처음부터 무한 반복
- 화면(창) 크기 대비 캐릭터가 작게 보이지 않도록 충분히 확대해서 그림
- 개발 과정을 20단계 이상으로 쪼개서 매 단계 커밋 (한국어 커밋 메시지)

## 3. 범위

**포함**

- 단일 파일 `Labs/LEC09/sonic_animation_viewer.py`
- pico2d 기반, 다른 외부 라이브러리 없음
- 스프라이트 시트에서 동작별 프레임 좌표를 직접 측정해서 하드코딩 (LEC08와 동일 방식)
- 창 닫기(X 버튼) 시 정상 종료 (`check_quit`/`quit_requested` 패턴)

**제외 (이번 과제 범위 아님)**

- 키보드 입력으로 동작 전환 (자동 순차 재생만 함)
- 실제 좌우 이동/점프 물리 등 게임플레이 로직
- 사운드

## 4. 기능 요구사항

| ID | 요구사항                                                                                                                                              |
| -- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1 | 스프라이트 시트에서 동작(행)별 프레임 좌표를 알파 채널 분석 등으로 측정해 리스트로 보관한다                                                           |
| F2 | 동작 하나당 프레임을 순서대로 그려 애니메이션처럼 보이게 한다                                                                                         |
| F3 | 동작 하나는 5회 반복 재생 후, 마지막 프레임에서 1초 정지한다                                                                                          |
| F4 | 모든 동작을 정의된 순서대로 재생하고, 끝나면 처음 동작부터 다시 반복한다 (무한 루프)                                                                  |
| F5 | 프레임마다 크기(가로/세로)가 달라도 캐릭터 발/기준점이 화면상 같은 위치에 고정되게 그린다 (LEC08의`clip_draw_to_origin` + `GROUND_Y` 패턴 재사용) |
| F6 | 창 크기(800x600 등) 대비 캐릭터가 잘 보이도록 확대해서 그린다                                                                                         |
| F7 | 창 닫기 버튼을 누르면 어느 동작을 재생 중이든 즉시 전체 루프가 종료된다                                                                               |

## 5. 비기능 요구사항

- **개발 프로세스**: 전체를 한 번에 작성하지 않고 최소 20단계로 나눠 구현하며, 각 단계마다 커밋한다. 커밋 메시지는 한국어로 작성한다.
- **재사용**: LEC08 `animation_viewer.py`에서 검증된 패턴(`check_quit`, `draw_frame`/`play_animation` 헬퍼, 발 위치 고정, 프레임 리스트에 출처 행 주석)을 그대로 가져다 쓴다. 바퀴를 다시 발명하지 않는다.
- **정확성**: 프레임 좌표를 잘라낼 때 스프라이트가 서로 픽셀 단위로 붙어있는 경우(LEC08 Jump 행에서 겪음)가 있을 수 있으니, 자동 분할 결과를 시각적으로 검증한 뒤 좌표를 확정한다.

## 6. 기술 접근 (LEC08에서 가져올 것)

1. `load_image`로 스프라이트 시트 전체를 한 번만 로드
2. 알파 채널 기준으로 행(동작) 경계와 열(프레임) 경계를 찾는 스크립트로 좌표 추출 (PIL 등으로 오프라인 분석 → 결과 좌표만 코드에 하드코딩)
3. `character.clip_draw_to_origin(left, bottom, width, height, x, y, w, h)`로 프레임마다 발 위치(`GROUND_Y`) 고정해서 그리기
4. 카메라 줌 패턴(`zoom_pos`/`zoom_size`, 기준점 중심 확대): 창 크기는 그대로 두고 보이는 장면만 확대
5. `play_animation(frames, repeats=5, hold=1.0)` 공통 헬퍼로 "5회 반복 + 1초 정지" 구현
6. `check_quit()`을 매 프레임(draw 할 때마다) 호출해서 반응성 확보

## 7. 마일스톤 (20단계 이상, 단계별 커밋)

1. `Labs/LEC09` 폴더에 `sonic_animation_viewer.py` 생성, `from pico2d import *`만 작성
2. `open_canvas`, `hide_lattice` 등 기본 캔버스 세팅
3. 스프라이트 이미지(`sonic-sprite.png`) 로드 코드 추가
4. 빈 `while` 반복 구조만 작성 (아직 아무것도 안 그림)
5. `check_quit()`/`quit_requested` 전역 상태 추가
6. 스프라이트 시트 알파 채널 분석 스크립트 작성 (오프라인, 행 경계 탐색)
7. 분석 결과로 동작 1(예: 달리기) 행의 프레임 좌표 확정 + 리스트로 코드에 추가
8. 동작 1의 첫 프레임만 고정 출력해서 좌표가 맞는지 확인
9. 동작 1 프레임 전체를 순회하는 애니메이션으로 확장 (아직 반복/정지 없음)
10. `draw_frame()` 헬퍼로 공통 렌더 로직(배경/캐릭터 그리기) 정리
11. `play_animation()` 헬퍼 작성: 5회 반복 구현
12. `play_animation()`에 마지막 프레임 1초 정지 추가
13. 동작 2 프레임 좌표 측정 + 리스트 추가
14. 동작 2 애니메이션 함수 작성, `play_animation()` 재사용 확인
15. 동작 3 프레임 좌표 측정 + 애니메이션 함수 작성
16. 동작 4(필요 시 추가 동작) 프레임 좌표 측정 + 애니메이션 함수 작성
17. 모든 동작을 순서대로 호출하는 메인 루프 작성 (한 바퀴만)
18. 메인 루프를 무한 반복(`while not quit_requested`)으로 변경
19. 화면 대비 확대(zoom) 적용 — 기준점 중심 확대 로직 추가
20. 확대 배율 조정 및 발 위치 정렬 확인/수정
21. 프레임 리스트에 출처 행 주석 추가 (유지보수용)
22. 전체 동작 순서대로 실행해서 눈으로 최종 확인, 필요한 미세조정

(실제 작업하면서 동작 개수나 버그 수정에 따라 단계가 더 늘어날 수 있음 — 그래도 무방함, 오히려 권장)

- [ ] 프레임이 바뀌어도 캐릭터가 위아래로 흔들리지 않음 (발 위치 고정)
- [ ] 창 닫기 버튼으로 즉시 종료됨
- [ ] 커밋이 20개 이상이고, 각 커밋이 의미 있는 단위로 쪼개져 있음
- [ ] 모든 커밋 메시지가 한국어로 작성됨

## 9. 리스크 / 참고사항

- 소닉 시트는 커비 시트처럼 행마다 라벨 텍스트가 없어서, 어디까지가 한 "동작"인지 시각적으로 먼저 확인해야 함 (얼핏 봐도 달리기, 구르기(스핀/볼 형태), 기타 포즈 등 최소 7~8개 행이 보임)
- 구르기(볼) 형태처럼 프레임마다 크기/중심이 크게 달라지는 동작은 발 위치 고정만으로는 부자연스러울 수 있음 — 필요하면 동작별로 기준점을 다르게 둘지 논의
- LEC08에서처럼 일부 프레임이 픽셀 단위로 붙어있어 자동 분할이 깨질 수 있으니, 분할 결과는 항상 잘라서 이어붙인 이미지로 시각 검증 후 좌표 확정
